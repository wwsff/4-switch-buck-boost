# 后续 STM32 固件对接检查表

2026-09-09 更新：已配套 `STM_POWER_CODE/STM_POWER_CODE` 下的 G474-DIAG-0.1.0 Keil 固件，使用协议 V2。实现阶段 A 的通信、标称换算测量，并加入 HRTIM 同步采样、故障锁存、停机、PID 参数及影子计算、快照和帧内日志；启动/自举刷新与 CV/CC 功率闭环尚未实现。以下清单是分阶段验收要求，不代表均已完成。实际 C 协议与上位机联调通过，未烧录或进行功率板实测。

## 阶段 A：测量和通信，禁止功率输出

1. 将生成的 `powerdesk_protocol.h` 纳入 MCU 项目，用固定长度 ring buffer 接 USART3 DMA/IDLE 数据；PC 使用 115200 / 8N1。
2. 在低优先级 FreeRTOS 通信任务解析完整帧，使用固定队列下发状态机请求。优先执行 STOP_ALL/OUTPUT=0。快速采样/电流 ISR 不解析协议、不打印、不等待 UART、不分配内存。
3. 实现 INFO、CAPS、STATUS、HEARTBEAT、STOP_ALL 和周期 TELEMETRY。INFO 上报 `PD_SCHEMA_CRC32`；CAPS 未开放功能为 0，ready=0，温度/电流未有效校准则清 valid 位。
4. 两通道均每秒上报 20 帧，可错开 25 ms。通道 2 未开放功率时仍回报状态和有效测量。不要为未实现通道伪造值或省略 CAPS/STATUS。
5. 通过 `test_vectors.json` 检查字节布局、CRC、seq/opcode/channel 回显。覆盖分包、粘包、CRC 错、长度错和未知命令。文本日志不得混入本串口。
6. 接上位机，检查量纲、零点、正负方向、温度、残压显示。确认断开/重连没有启动输出。

V1 只支持 PC 单控制源。FDCAN2 可以继续启用外设和只读监测，但不得与 UART 同时修改目标、PID 或发起启动；任何已实现来源的 STOP 均应优先受理。后续若接屏幕控制，需要另行版本化控制权/会话仲裁协议，不能继续使用旧文本协议的 CLAIM/session 字段与本帧混合。

## 阶段 B：保护和受限调试

1. 先完成安全启动/停止、自举刷新、硬件 Fault 输出抑制与故障锁存、通信超时、ADC 有效性检查。修正已知 CubeMX Fault blanking 生成设置并读回验证。
2. 完成 HRTIM 同步 IL 采样和固定 RAM 快照，匹配基础速率/抽取/有效测量；缓冲最多 256×20=5120 字节。UART 上传和故障停机不得争抢快环时限。
3. GET_PID/SET_PID 严格遵循 PROTOCOL.md 的单位、Ts、D 对测量及抗积分饱和约定；无效参数/运行中写入必须 NACK，不能忽略后返回 ACK。
4. SET_TARGET 原子更新 V/I 两个目标，状态机限斜率。当前首轮硬件只开放 CH1；CH2 的能力、范围、ready 反映真实未开放状态。
5. IL 调试先本地固件定时停止验证，再开放 features.bit1。确认重复启动不能延时、断开主机仍到时关断、空载/负载变化下过压保护有效。
6. 硬件验收后才提高 CAPS 范围/置 ready，不能从 PC 命令直接解除验收门槛。

## 阶段 C：闭环运行

1. 电流内环验证完成后接电压外环与输出恒流限制，确认 Iout 与 IL 不混用。输出模式/状态/测量与上位机严格一致。
2. 启动和故障动作实测 EN、栅极 VGS、死区、自举 HB-HS 和输出波形。不能以界面 ACK 或 enabled=0 代替示波器验证。
3. 覆盖拔 USB、关闭页面、冻结 PC、MCU→PC 单向丢数、短时 Fault 脉冲、通信恢复后不自动重启。
4. 每个已完成版本执行适用测试并做本地 Git 提交；协议变更同时修改 schema、文档、生成文件、PC 与 MCU 测试。

## 接口实现优先级

先能连接并看真实测量 → 安全状态机与快速采样 → PID 参数读写/快照 → 单路 IL 调试 → 单路 CV/CC → 模式扩展和第二路。

真实保护阈值、环路增益、自举时序、支持范围仍由硬件确认决定。演示设备中的任何参数都不能作为固件的生产默认参数。
