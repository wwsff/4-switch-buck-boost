# 桌面电源——四开关Buck-Boost版本

一套基于 **STM32G474 功率控制板、STM32H750 屏幕板和 PowerDesk 电脑上位机** 的可调直流电源项目。

本项目采用四开关非反相 Buck-Boost：通过输入、输出两侧半桥联动调制，实现输出电压低于或高于输入电压。输出为正极性直流，不是产生正负交替输出的逆变器。功率调节和保护由 G474 执行，H750 负责本地操作和显示，PowerDesk 用于电脑操作、监测与调试记录。

**发布定位：实验开发版本。** 已有实物功能验证，但还没有完成所有电压、电流组合的满载、热稳态和故障验收。本文把“代码已实现”“作者实物确认”和“尚未测试”分别说明，避免把设置范围当作额定能力。

说明核对日期：**2026-10-09**。硬件工程位于发布包的 `板子/` 目录，格式为 `.epro2`；本文只介绍软件与操作，不提供硬件绘制或制作教程。项目原创软件及配套文档采用 **GPL-3.0许可证**，原创硬件工程保留 **MIT许可证**，具体范围见文末。

## 1. 先看已完成的功能和效果

|---|---|---|
| G474 固件 | 功率控制板 | CH1 电压闭环、慢速输出限流、双桥联动、软启动、受控降压、故障锁存、自动输出电流校零、采样与遥测、CAN/串口通信、NTC温度换算 |

### 1.3 当前可以设置的范围

| 项目 | 当前软件配置 | 如何理解 |
|---|---|---|
| CH1声明输出电压 | 2～44 V | 目标值范围；硬件实际可达范围还受输入、负载、损耗和调制行程限制 |
| 通用输出电流设定上限 | 5 A | 输出电流限制的参数上限，不是保证能持续输出5 A |
| G474启动/运行输入窗口 | 19～21 V | 程序允许的窗口；项目实际输入最高约20 V，21 V只保留作前期实验条件 |
| 开关频率 | 250 kHz | 当前配套配置，不建议复现者首次使用就修改 |
| 电压控制/慢限流周期 | 1 kHz | 当前控制架构没有完成电感电流内环闭环 |

设定电流是**限值**。例如43 V接200 Ω负载，即使限流设为3 A，负载正常也只需要约0.215 A；电源不会主动把电流提高到3 A。

## 4. 先选一种控制方式

有屏幕时建议使用H750本地控制；没有接入CAN控制端时，可以用PowerDesk通过串口控制G474。两者的控制权不是并列的。

| 使用方式 | 谁下达设定和启停 | PowerDesk能做什么 |
|---|---|---|
| H750未通过CAN接管 | PowerDesk串口控制 | 参数下发、启停、读取状态、导出日志等 |
| H750已通过CAN接管 | H750 | 主要读取状态、日志、快照；多数写命令会被G474拒绝 |
| CAN接管后又断开H750 | 不自动转交串口 | 应处理通信故障；需要按下面流程重新选择控制方式 |

G474第一次收到有效CAN命令或心跳后，将控制权归CAN，直到G474复位。如果此前串口已经开启输出，接管过程会先停止输出。CAN接管后，串口心跳不会给CAN控制的输出续命。

**从H750切换为PowerDesk控制：先用H750停止输出，停止CAN控制端发送，然后复位G474，再连接PowerDesk并等待自动校零。** 只拔掉CAN线不会自动让串口取得控制权。

PowerDesk的“全部停止”同样是串口写命令，在CAN已经接管时不能当作可用的独立急停。正常操作应使用当前控制端的STOP；故障时的断电处置按实际台架设计执行。

## 5. 编译和烧录

### 5.1 直接使用配套HEX

这适用于与作者硬件和本版本配置一致的复现。

1. G474使用：`代码/STM_POWER_CODE/STM_POWER_CODE/Bench/20261008-ntc-can/STM_POWER_CODE.hex`。
2. H750使用：`代码/STM_POWER_LCD/STM_POWER_LCD/Bench/20261008-ntc-can/STM_POWER_LCD.hex`。
3. 用各自芯片对应的下载设置写入。HEX包含地址信息，不需要把H750镜像写到外部QSPI；本版本程序运行在内部Flash。
4. 上电后读取日志版本，确认分别为本说明第2节的字符串。
5. `SHA256SUMS`保存配套文件校验值；使用修改过的源码重新构建后，应记录新的镜像哈希。

HEX与AXF分别属于对应MCU，不可互换。AXF主要用于带符号调试，不是PowerDesk的输入文件。

### 5.2 从源码构建

1. 解压或克隆整个项目，保留上面的目录结构。
2. 用Keil分别打开两个`.uvprojx`工程。
3. 确认目标芯片分别为`STM32G474RETx`、`STM32H750VBTx`，选择ARM Compiler 5，并补齐设备包。
4. 分别执行Rebuild，查看完整构建日志。
5. 当前工程输出位置为各自的`MDK-ARM/ReviewBuild/`；以实际工程设置和本次日志为准，避免烧录旧Release里的HEX。
6. 记录版本、提交、HEX校验值，再下载到对应板子。

当前H750配套配置为 **8 MHz外部晶振、225 MHz系统时钟**。不要照搬旧文档里的25 MHz晶振参数。使用不同核心板时，需要先核对时钟来源和CAN参数。

### 5.3 只有修改配置时才重新生成

CubeMX打开后持有一份内存配置；其他工具修改磁盘上的IOC，不会自动更新这份内存。应关闭旧窗口且不保存，再重新打开当前IOC。

按第2节解压后，H750生成操作结束，从`代码/STM_POWER_LCD`目录执行：

```powershell
python tools/fix_keil_project.py
python tools/check_ioc.py
python tools/check_ioc_intent.py
```

第一个命令将独立`User/`代码和头文件路径重新接回Keil工程；后两个检查IOC、生成代码和配置意图。执行完仍需重新构建。G474的`App/`与工程文件列表也要保留，不能把重新生成后的空应用工程直接当成完整固件。

不要为了消除编译错误随意更改PWM频率、死区、ADC采样相位或保护宏。它们影响功率级行为，并非普通界面设置。

## 6. 第一次上电：先校零，再尝试小功率输出

### 6.1 自动准备过程

当前G474上电后保持输出关闭，并自动测量CH1输出电流零点。开始校零需要满足：

- CH1输出关闭，正常模式，无锁存故障。
- 输入电压处于校零窗口18～22 V；**启动输出另有19～21 V窗口**，两个窗口含义不同。
- 输出残压不高于200 mV，无外部电源向输出端灌电、无实际输出电流。
- VIN/VOUT/IOUT测量及采样健康检查有效，功率使能和PWM处于关闭状态。

条件连续满足约500 ms后开始采集4096点。采样及稳定检查通常需要几秒；零点只在满足检查后应用，失败则保持输出锁定。本版本每次G474复位后重新准备，**不需要先打开PowerDesk再手动校零**。

串口日志中可关注：

```text
AUTOZERO waiting ...
AUTOZERO IOUT started; output stays OFF
AUTOZERO IOUT ready; output may start if other checks pass
```

第三行表示校零已经应用，其余启动检查还必须满足；它不是“电源已经开启”。校零只修正电流零点，不负责标定电流增益，也不消除全部噪声。

### 6.2 用H750进行第一次输出

1. 按配套硬件说明接好两板CAN和供电，先保持输出关闭，使用限流台架输入。
2. 确认H750收到了G474：不再显示`NO DEVICE`，并等待`PREPARING`结束。
3. 设定 **5.00 V / 0.30 A**，接一个适合小功率试验的20 Ω负载。该示例正常负载电流约0.25 A、功率约1.25 W，负载须有足够连续功率与散热能力。
4. 按K1或触摸`SET`提交设定。等待确认，不要把正在编辑的数值当成设备已经接受的目标。
5. 触摸`START`，观察状态由启动过渡到`OUT ON`，并用万用表确认实际输出。
6. 触摸`STOP`，确认输出已关闭；输出电容可能仍有残压，关闭输出不等于端口电压立即为0。

首次试验不要直接设为43～44 V或5 A。若显示准备失败、故障或参数被拒，先记录日志和当前输入/输出状态，再处理原因。

## 7. H750屏幕怎么操作

当前界面为 **320×240横屏、英文点阵字体、CH1单路显示**。顶部为连接状态；中部显示实际电压、电流与编辑中的设定值；下部显示输出/故障状态与触摸按钮。

### 7.1 主页面操作

| 操作 | 作用 | 说明 |
|---|---|---|
| 旋转编码器 | 增减当前字段的设定值 | 先编辑，不立即发送 |
| 按编码器 | 切换调节步长 | 电压0.01/0.1/1/10 V；电流0.01/0.1/1 A |
| K2 | 切换电压/电流字段 | 切换后回到该字段最细步长 |
| K1 | 提交当前电压和电流限值 | 等待G474确认 |
| 触摸`SET` | 提交设定 | 与K1同类操作；温度页同位置是`BACK` |
| 触摸`START` / `STOP` | 开启 / 停止输出 | 标签随实际状态变化 |
| 触摸`CLR` | 请求清除故障 | 故障原因仍存在时不能靠反复清除继续运行 |
| 触摸左上角`POWER>` | 打开温度页 | 可继续查看功率状态 |

当前生成代码中K1对应PE6、K2对应PE5。物理外壳若标号不同，以实际板子和固件功能为准；不要沿用旧文档里相反的按键说明。

编辑中的设定值会有待提交标记。命令ACK只表示请求被接受，**输出开启状态来自G474的实际回报**，不是按下START后本地直接改为开启。未确认的目标或通信失败会被明确显示，界面不会自动重新启动离线设备。

触摸时出现5×5红色小点，用于显示触点位置，约5 s后消失。它是交互反馈，不是故障灯；局部恢复避免每次触摸都整屏刷新。

### 7.2 常见状态含义

| 显示 | 含义 | 下一步 |
|---|---|---|
| `NO DEVICE` / 离线 | 没有可用功率板数据或链路已失效 | 检查两端固件、供电、CAN与日志；不要按显示数字推断真实输出 |
| `PREPARING` | 功率板正在等待或进行启动准备 | 保持输出关闭，检查输入与残压，等待校零 |
| `INIT ERROR` | 启动准备失败 | 查看G474 ZERO/故障日志，处理原因 |
| `STARTING` / `STOPPING` | 启动/停止过渡 | 等待实际状态，不连续重复操作 |
| `OUT OFF` | 输出未启用 | 仍可能有输出残压 |
| `OUT ON CV` | 恒压运行 | 电流由负载决定 |
| `OUT ON CC` | 限流运行 | 为不超过设定电流，输出电压可能下降 |
| 故障文字 | G474锁存了故障 | 先停机和查原因，再清故障；清除不会自动开启输出 |

### 7.3 温度页

点击左上角`POWER>`进入温度页；点击顶部`TEMP`或下方`BACK`返回。显示MOS附近和电感附近两路NTC温度，支持负温度；温度页禁止编码器、K1/K2修改隐藏的设定值。

| 显示 | 含义 |
|---|---|
| 正常温度数值 | 收到有效测量，显示到0.1 ℃ |
| `WAIT DATA` | 尚未收到温度报文 |
| `STALE` | 温度报文超过约1 s没有更新 |
| `SENSOR ERR` / `--.-C` | 测量无效，例如传感器异常或采样不合格 |
| `NO DEVICE` | 功率板不可用 |

温度通过G474采集，经CAN发送给H750。读数代表 **NTC所在位置的温度**，不是MOS结温。当前`PD_NTC_VERIFIED=0`，温度已用于显示/诊断，**尚未启用新增过温停机功能**。

## 8. PowerDesk怎么使用

### 8.1 安装与启动

按第2节将上位机解压到`代码/PowerDesk`，进入该目录，在终端执行：

```powershell
python -m pip install -r requirements.txt
python server.py
```

Windows也可以在依赖安装完成后双击`Start_PowerDesk.bat`。它启动本机服务并打开默认浏览器。保留服务窗口；浏览器地址由服务打印，例如`http://127.0.0.1:实际端口`。

服务仅监听本机，默认自动选空闲端口，不依赖云端账户。不要直接双击`web/index.html`或通过`file://`使用界面。

如浏览器没有自动打开，可执行：

```powershell
python server.py --no-browser
```

然后复制服务窗口中打印的地址到浏览器。需要指定端口时可使用`--port 端口号`。

### 8.2 先体验演示，再接实物

点击“进入演示”可熟悉设定、趋势、故障显示和导出操作。演示不会连接实际COM口，数字是合成数据，**不是电源仿真结果或真实硬件性能**。

连接实物时：

1. 退出占用该串口的串口助手，选择G474控制板对应的COM口。通信为115200、8N1。
2. 首次使用可关闭页面“自动恢复”，先观察新版G474自身自动校零。旧版PowerDesk保留设备记录恢复逻辑，不能把它的提示当作新版固件仍必须手工确认映射。
3. 点击连接，检查握手版本、通道能力和实时状态。
4. **如果CAN已经接管，本次连接只按监测/诊断使用。** 出现写命令BUSY并非一定是串口坏了。
5. 需要电脑控制时，先按第4节切换控制方式，再“应用设定”，最后独立点击“开启输出”。输入框变化本身不会开启输出。

输出电流限制、设备已接受目标、实际测量是三种不同信息。实际测量不要被设定值或编辑中的数值替代。

### 8.3 电流模式与滚轮

PowerDesk按设定电压自动切换提示和电流输入上限：

| 设定电压 | PowerDesk显示模式 | 界面电流上限 |
|---|---|---|
| ≤30 V | 大电流模式 | 最多5 A，同时不超过设备上报的能力 |
| >30 V | 高压模式 | 最多3 A，同时不超过设备上报的能力 |

电压输入框每次滚轮变化0.1 V，电流输入框每次变化0.1 A；手动输入支持更细的数值。模式规则用于限制设定参数，不会让负载自动吸取该电流。

**这个30 V分界目前只在PowerDesk网页界面自动强制。H750和G474仍按通用5 A能力接收参数，没有固件级“高压最多3 A”规则。** 使用H750做>30 V实验时，请手动将限流设为不高于3 A；这一操作约束不是设备已经实现的强制保护，也不能理解为44 V/3 A已经验收。

### 8.4 记录与调试

- 导出诊断日志和测量CSV时，记录固件版本、输入电压、目标、负载、测量方法及时间。日志文件名不能替代内容核对。
- 日常趋势是低速遥测，不能用于测开关纹波或纳秒级死区。
- 快速快照可选择64/128/256点与抽取系数；是否可用以设备能力为准。它是一次采样记录，不提供自动频响分析或PID自动整定。
- **当前PowerDesk PID页面写入的参数，不等于当前CH1功率CV/CC环参数已经改变。** G474实际电压/限流环仍使用编译在配置中的参数；部分参数用于存储或影子诊断。首次复现无需通过PID页调参才能输出。
- 当前`PD_IL_SENSOR_FITTED=0`，不要使用“电感电流调试”页面把不存在的IL测量当成真实闭环功能。
- 上位机代码更新后需要退出旧Python服务再启动，只刷新浏览器不会加载新的后端代码。

## 9. 保护、断线和本版本限制

本版本已实现采样健康检查、输入窗口、输出过压判定、调压失败停止、通信超时和故障锁存等软件处理。但实验版本的保护完整性必须按当前装配、宏和实物结果理解。

| 项目 | 当前行为 | 使用边界 |
|---|---|---|
| 输出慢限流 | 电流超过设定值时降低控制参考，进入CC | 不是快速短路硬件关断 |
| 输入窗口 | 当前19～21 V内才能正常启动/运行 | 在项目约20 V输入条件下复现；不要用提高输入绕开不可达工作点 |
| 输出过压 | 参考与软启动/降压过程配合；有持续判定 | 保护动作尚未完成全部实物验收，不是精密电压钳位 |
| 调压失败 | 达到调制行程终点仍不能满足目标时停止并报故障 | 能接受目标不保证能稳住目标 |
| 通信超时 | H750约每250 ms发送心跳；G474约1 s无有效控制心跳锁存通信故障 | 串口在线不能掩盖已接管CAN的掉线 |
| 快速IL/OC保护 | 默认IL传感器未装，相关路径退出 | 不能宣传完整硬件短路保护；实验台架应有合适的输入限流 |
| 温度 | 有测量与错误/陈旧提示 | 新增过温停机未启用 |
| 量程预判 | 当前`PD_RANGE_PROBE=1`，实验探针模式放宽了原可达性预判 | 不属于正式量程保证，供逐步验证高压点 |
| 第二路输出 | 默认未装 | 不属于已完成双路版本 |

PowerDesk失去页面轮询、设备遥测或连接后，会尝试停止并停止续发心跳。电脑休眠、关浏览器或拔线时，最后一条软件停止命令可能无法送达，需要G474自身通信保护处理。因此当前版本不作为无人值守输出保持方案。

对首次复现者，最重要的三点是：**先小功率验输出；限流值不是输出能力；停止后确认实际端口残压。** 温度显示正常、测试通过或界面显示OUT OFF，都不能单独代替对异常工况的检查。

## 10. 常见问题

| 现象 | 优先检查 |
|---|---|
| H750显示NO DEVICE | 两板是否配套版本、G474是否运行、CAN供电/连接/两端终端、两端是否500 kbit/s |
| 显示PREPARING不结束 | 输入是否满足校零条件，输出是否放电到≤0.2 V，是否有故障或采样问题；查看AUTOZERO与ZERO blocked日志 |
| 显示INIT ERROR | 查看校零噪声/越界/超时等原因；不要靠连续按START跳过准备 |
| PowerDesk显示BUSY或不能下发 | CAN是否已接管；是否需要先停止CAN发送并复位G474切换控制端 |
| “查询零点”显示未校准 | 查询只读状态；新版先等自动校零，不能把查询当成启动采集 |
| COM口能看到却打不开 | 是否被其他程序占用；驱动及COM名称是否有效。PowerDesk对部分Windows名称异常有回退，但仍需看日志确认实际设备 |
| 设3 A却只有0.2 A | 先检查负载。43 V/200 Ω正常约0.215 A，限流不是恒流目标发生器 |
| 高电压够不到目标并报内部故障 | 看实际输入、负载和调制饱和；声明44 V不等于所有输入/负载下可达 |
| 温度显示--.-C或STALE | 检查两端版本、NTC有效状态、温度报文是否持续更新；别把无效值当正常0 ℃ |
| 输出停止后仍有电压 | 可能是输出电容残压；用仪表确认并按台架方式放电 |
| CubeMX生成后界面功能消失 | 检查H750 User文件是否仍进入Keil工程，运行fix_keil_project并重新构建 |
| 修改PID页后效果不变 | 该页部分参数未接入真实CH1功率环，见第8.4节 |

报告问题时建议提供：两端版本/提交、实际操作顺序、输入电压、目标V/I、负载、实测输出、完整诊断日志。需要波形时注明探头接法、带宽和测点，不只写“有尖峰”或“不能用”。
